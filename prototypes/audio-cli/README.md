# 音频原型（阶段 1）

命令行程序，用于在接入 UI 之前验证 Core Audio 的读写和变化监听。
代码结构与将来的 `src-tauri/src/audio/` 保持一致，阶段 2 直接迁移。

## 运行

```text
cd prototypes/audio-cli
cargo run
```

启动后会打印设备、系统音量和应用列表，输入 `help` 查看全部命令。

## 模块

| 文件 | 内容 |
| --- | --- |
| `src/audio/thread.rs` | 音频线程（COM MTA）、消息循环、会话表、按应用聚合 |
| `src/audio/device.rs` | 默认输出设备、系统总音量、设备变化通知 |
| `src/audio/session.rs` | 单个会话的音量读写与回调 |
| `src/audio/app_info.rs` | 由 PID 推断 AppId 和名称 |
| `src/metrics.rs` | 本进程内存与 CPU 时间 |
| `src/main.rs` | 命令解析 |

## 实测数据

- 常驻内存：工作集约 11–15 MB（debug 构建，4–5 个应用），多次切换设备后无明显增长。
- 空闲 CPU：空闲 90 秒前后累计 CPU 时间均为 0.016 秒，无轮询。
- 2026-09-29 用户实测时，`app 0` 对网易云音乐的每次修改打印了两次；随后单独复现只打印一次。推测当时该应用有 2 个会话（每个会话各回调一次）。正式版在后端按应用合并事件（见 architecture.md），届时需确认只推送一次。

## 已知限制（留到阶段 2）

- 不提取图标；UWP 应用名称暂用 exe 的 FileDescription。
- `@%SystemRoot%\...` 形式的会话显示名不解析。
- 没有请求合并（拖动滑块时的节流在接入 UI 时实现）。
